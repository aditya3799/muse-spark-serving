# Muse Spark expert execution and cache allocation

This patch reduces expert-parallel MoE overhead, avoids redundant projection work, and reuses compatible FA3 verification scheduler metadata. The submitted launch configuration allocates more of the existing KV budget to full-attention tokens through SGLang's standard cache-ratio flag.

## Launch configuration

- `--moe-runner-backend humming`
- `--swa-full-tokens-ratio 0.35`

The cache ratio is constant across all requests and loads. It changes the capacity split between full-attention and sliding-window pools through the existing allocator; it does not shorten attention windows or truncate prompts. The judge's `--mem-fraction-static 0.85` remains in effect.

## Source changes

- Humming expert execution uses canonical NVFP4 weights and FP8 block scales, FP32 accumulation, and the existing BF16 output boundaries. Device-side histograms partition local routes between compatible light and heavy expert configurations, retaining the original K-reduction geometry in the larger-prefill path. Configuration admission occurs before capture, with fallback for unsupported cases.
- Routing metadata is prepared for reuse, including expert lookup maps and small-route alignment. The Marlin path retains guarded adaptive tile selection for applicable sparse expert-parallel geometry.
- Expert finalization separates per-expert RMS reduction from tiled weighted combination. The source credits the public MoE decomposition that informed this implementation.
- Guarded tensor-parallel projections shard token rows for larger replicated projections or output columns for eligible small projections, gathering the complete outputs in their original order.
- FA3 target-verification scheduling metadata is reused only when attention geometry matches. Sliding-window, local, cross-attention and unsupported masking cases retain their existing paths. This patch does not introduce a new attention exponential approximation or lower-precision attention arithmetic.
