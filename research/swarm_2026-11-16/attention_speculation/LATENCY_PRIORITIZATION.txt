One additional exact-computation prototype worth testing
-------------------------------------------------------
Vectorize the sequence-length prefix calculation in
sglang/python/sglang/kernels/ops/attention/metadata.py:
_fused_decode_metadata_kernel, lines~239-249.

Current pid_b==0,pid_c==0 executes a runtime for idx in range(B), loading one
sequence length and advancing acc serially for every request. It writes
cache_seqlens and exclusive cu_seqlens in the same metadata launch used by
normal decode and target verification. This is a concrete source dependency
chain, not an observed H200 bottleneck.

Candidate algorithm: a shape-derived power-of-two BATCH_BLOCK, masked vector
load of seq_lens, cast each seq+delta to int32 exactly as today, masked zeros,
tl.cumsum of valid values, vector writes of lengths/exclusive prefix and one
write of final sum. Retain the current page-table construction unchanged.
For large unsupported scan sizes retain original loop; no data-dependent
workload dispatch, host tensor reads, persistent input cache or changed
attention arithmetic. The batch shape is static per graph bucket.

Correctness contract: preserve every live cu_seqlens entry including0/B,
int32 conversion/overflow semantics, noncontiguous input/output strides,
B=1/non-power-of-two batches, positive/zero delta, and padding rows. Updating
request sequence lengths in graph replay must update all results. Reject
negative/invalid lengths only if existing API does; do not add new contract
restrictions. Masked lanes must never contribute delta. Preserve original
behavior for B=0 (no launched grid) and unusually largeB via fallback.

Decisive tests once GPU returns: exact old/new kernel output comparison for
B=1,3,4,7,8,17,32,65 and strided buffers across page1/16/256; sentinels outside
the live write region; changing-input replay across buckets; source-level
precision equality; paired A/A then A/B events with routing/attention absent
to isolate metadata, plus whole metadata+attention chain to bound benefit.
Native CPU can validate layout bounds/AST/dispatch now, but cannot validate

these pass. Expected impact incremental, not a stand-alone1.6x mechanism.
