Precision and paths
- Single-token/ordinary fused kernel, inverse-RMS kernel, and tiled combine each
  load BF16 x and scale, multiply in FP32, explicitly convert to BF16 then back
  to FP32 BEFORE the unchanged norm/reduction operations. AST checks prove those
  arithmetic tails remain identical. Both split kernels recompute the same
  rounded value; neither uses raw x for its norm or combine.
- The no-ID eager fallback cannot receive a scale: wrapper requires IDs first.
  Humming _forward_marlin refreshes the current norm cache before deciding to
  defer. Recognized norms pass the scale to the fused finalizer; arbitrary norm
  fallback keeps helper scaling. Direct helper calls default to scaled outputs.
  Stock Marlin passes no scale. Norm-object transitions passed exact-method spies.
- All scale and x reads stay inside live (expert ID>=0) branches; inactive
  storage remains undefined but is not read or reduced. All-inactive outputs
  retain the zero-accumulator behavior. The inv-RMS kernel stores zero for dead
  slots and tiled combine skips them. No scalar host read or new synchronization.

Memory/capture and assumptions
- The scale vector is the persistent registered w2_post_scale buffer. The new
  paths add no full activation allocation and no invocation-tensor cache; inv
  storage is unchanged. Host guards use only dtype/device/shape/contiguity.
  In-place scale/ID changes between replays should be seen by both kernels.
  As in the old path, replacing a captured buffer requires recapture; mutations
  between the two split-kernel launches are unsupported concurrent modification.
- Scale IDs must be either negative or within the local scale vector. There is
  no hot-path host range check, matching the previous scaling helper's contract
  and the dispatcher's local mapping. Do not claim support for out-of-range IDs.
- Norm weights/epsilon are handled by the pre-existing norm cache; mutating the
  same norm object behind that cache was not newly solved by this change.
