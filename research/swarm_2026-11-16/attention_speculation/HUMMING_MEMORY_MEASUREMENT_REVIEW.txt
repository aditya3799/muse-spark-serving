Scope
One synthetic local expert layer: E=32, global E=256, H=I=4096, top-k=8.
Fresh processes; retained original tensor storage through the complete prepare
call in both modes, then released at simulated loader-context exit. Shared graph
pool and capture stream, largest-first buckets 256,128,32,8,1, one largest set of
input buffers sliced for smaller buckets. Every captured graph reports pool[0,1]
within its own process. Pool IDs are process-local, not cross-process sharing.
Source-minimal runtime omitted package initializers, but selected arithmetic
function bodies were unmodified; this is not a full serving construction test.

After-allocated is always exactly 7,680 bytes higher for Humming. For BOTH paths,
each captured bucket increases after-allocated over before-allocated by exactly
M*4096*2 bytes: 2,097,152; 1,048,576; 262,144; 65,536; 8,192. These are precisely
the retained final output sizes. Thus this probe shows scratch reuse with no
extra per-bucket persistent activation storage. Reserved memory does not grow
monotonically by scratch size; temporary warmups/allocator packing still affect
its peaks. Major cache13/cache2 storage equality from the source audit remains
consistent with these measurements; lower transient peaks do not mean those
nominal buffers disappeared.

Evidence limits retained
1. Single layer, only M<=256 and this synthetic shape/routing, local SM86. No
   full-model sequential layers, actual prefill token sizes, target/draft graph
   interactions, real EP/TP communication, or H200 WGMMA memory was measured.
2. PyTorch allocator metrics exclude external CUDA driver/module/graph overhead.
   There is no device-level peak memory trace in these JSON files.
3. Shared-pool capture is tested, but serving GraphPoolPrecarve, graph borrowing,
   full output-buffer policy and KV sizing lifecycle are not instantiated.
4. Source-minimal helper extraction bypasses full loader/model construction. The
   retained-originals fixture matches the audited preparation storage lifetime,
   but it is not a full-model loading peak. Stock helper also retains original
   data aliases itself throughout preparation; there is no demonstrated unfair
   early-release advantage for stock in this final harness.
5. Live-buffer replay checks verify all-inactive zero output and finite active
   output. Numerical equivalence belongs to separate frozen-helper tests. After
   the first bucket's replay mutations, smaller buckets use all-local routing;
   this is matched A/B allocation evidence, not realistic workload timing.
6. One fresh process per arm establishes this observed pair, not allocator
   variance over repeated runs. No speedup can be inferred from memory peaks.

Disposition
Local preparation and graph-memory validation is improved and shows no material
regression. Keep root's full-model H200 memory gate open: run matched complete
stock/candidate startup, capture and replay, including the full combined package,
per-rank device-visible and allocated/reserved peaks, and unchanged KV sizing
inputs. Equality of final free memory after automatic KV resizing is insufficient.
