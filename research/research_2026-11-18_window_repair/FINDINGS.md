# DFlash prefill and arbitrary prefix reuse

The scored 1.2363 parent materializes five draft-layer K/V pairs for every prefill token. The public draft checkpoint has five sliding-attention layers with a 2,048-token window. Many early chunks in a long cold prompt can never reach its first draft query. Another request can later fork into those chunks. Skipping draft rows safely therefore requires a way to identify and repair such a hit before the shorter request decodes. Its SHA256 is `0238159e2bdbeb5e4e09abc9772d903af0c014ef17cf3830409f062d7dae5182`. The implementation tracks potentially unwritten K/V using a bounded, monotone 1 MiB Bloom filter. Each region key includes the original cache salt, extra key, and all tokens preceding the region. Before a reuse match, the scheduler can cap the hit to rebuild a potentially missing part of the live window. It suppresses checkpoint publication where canonical old slots could overwrite repaired live rows. The ordinary first chunk remains materialized. ## Score evidence

The 49,152 omitted rows correspond to a 2.965× linear-time upper scenario for that cold-first-turn component. Going from 1.2363 to 1.8 would require it to account for 47.25% of all baseline elapsed time under a simple throughput model. Going to 2.0 would require 57.61%. The official score combines concurrency/latency curves and cannot be inferred from a linear component model.

The 74,160-token single-SM86 run exceeded its allotted local queue slot while still in its first unmeasured group. It reported about 3.65 GiB of total GPU memory and a 210 MHz clock. No throughput observation was accepted. A smaller multi-chunk fixture keeps the real 2,048-token window and the full 40,960→8,192 BF16 projection. It covers a 7,953-token cold request, an ordinary extension, an interior fork with extra target rows, and a mixed fallback. It uses independent synthetic weights and activations, the configured RoPE, native RMS normalization, five original draft K/V layers and the native NHD fallback scatter. Target rotary/transformer work, true distributed collectives and the real radix state machine are outside these local timings.

Dynamic attachment of an external persistent cache and streaming-session slot reuse remain separate deployment qualification cases. The nonlinear official score, actual H200 time fraction and whether cold targets use eager or captured target-tap collection remain unmeasured.

## Bounded local result

The fresh 7,953-token pilot used the actual DFlash and target methods above with synthetic upstream residuals, independent FC/KV weights and changing activations. The warmup and first timed round each matched all required five-layer K/V entries across all four scenes. The mixed case runs the short request to its first query, continues the long request through its terminal window, and checks both. The timed round compared 10,506,240 BF16 entries. It took 6.164 s parent and 3.970 s candidate on cold prefill, 0.634 s and 0.606 s at a cached 753-token tip, 0.584 s and 1.419 s at the repaired interior fork, and 3.981 s and 4.316 s on the full mixed case. The baseline-copy cold arm took 7.521 s. A later synchronous host-to-device metadata transfer stalled on the local SM86 GPU and the shared GPU was released. The controller marked this experiment **INCOMPLETE** with no reward.
