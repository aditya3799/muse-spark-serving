# Overlapping DFlash context projection with target verification

The scored worker queues the target graph, finishes target TP selection or gathered sampling, determines committed prefix lengths, publishes next sequence lengths, and only then calls the draft model’s context projection. For this DFlash2 model the projection is one replicated native BF16 linear from 40,960 to 8,192 features followed by local RMSNorm. Its dense input covers every verify row. Accepted lengths are first needed by the KV publisher. All ranks' existing TP decisions can remain in their original order. The second candidate starts the same FC earlier. The target logits processor already assembles the packed auxiliary array before launching the vocabulary projection. A separate external CUDA event belongs to each eligible captured graph variant and signals at this boundary. The worker clears the marker on its returned output to avoid prolonging auxiliary-buffer ownership in scheduling.
