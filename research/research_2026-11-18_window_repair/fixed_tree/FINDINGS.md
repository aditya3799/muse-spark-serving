# Eight-row DFlash tree verification on the scored serving parent

**Decision.** Held-out real Qwen3-1.7B + DFlash2 trajectories allow a 5.15% increase in verification-step time at break-even for the deployable, fixed-eight, no-unary-mass proposal. The 95% request-resampled interval for the verifier-call ratio is 0.959–1.137. The local implementation adds substantial metadata work at long context. These results provide insufficient support for a 1.8× serving score. The source patch is experimental. [Segment and call replay](segments_replay.json)

## Worker entry and physical ownership

The cumulative source patch applies to pinned SGLang commit `297e54fd105e974cdf401e5b4d20253a22c16f90` and includes the scored 1.2363 patch with SHA-256 `8c7547213fb993a318321a26f84e2872db8c87b358ee3d3ea638695702b0dc2b`. Supported folded DFlash selector captures retain the same conditional logits that feed their normal seven-token walker. Every native draft row keeps the parent’s absolute ordinal position. Tree growth supplies eight target tokens and replaces target positions with committed prefix length plus the node’s depth. ForwardBatch takes these positions from DFlashVerifyInput before the target applies rotary embeddings. Local TP ranks agree on the 160 bytes/request packed topology with one broadcast. [Patch and SHA](patch.json) · [Cumulative source](candidate.diff)

The stock chain FA3 branch does not consume a tree mask. Setting EAGLE top-k changes capture-time buffers, its full-attention path uses separate prefix and suffix softmaxes and then merges rounded output tensors. A small numerical example uses an all-zero query, prefix values −0.5, −0.5, 0 and suffix 1. A single joint softmax yields exactly zero. With BF16-rounded partial results, the weighted merge yields −0.00048828125. This arithmetic example documents a difference that the two-stage algorithm can introduce. The scored native kernel has not been run on this example. [Numerical fixture](rounding.json) · [Pinned FA3 dispatch](../../sglang/python/sglang/srt/layers/attention/flashattention_backend.py)

The research worker marks eligible greedy page-one verification steps before graph admission. The decoder graph runner explicitly rejects this marker since its ordinary eligibility flag only applies in configurations requiring MLP synchronization. The marked target runs eager. Its standard KV write still executes, then the FA3 target issues one ordinary causal softmax per node over common prefix plus ordered ancestors. Sliding layers use at most 2,048 contiguous logical pages, with unchanged precomputed rotary positions. Native FP8 K/V descales are expanded to the number of logical query sequences, B×8. Full and sliding maps either derive from distinct unified tables or from static full identity and the pool’s actual sliding mapping.

After target greedy selection, ranks agree on the decisions using the existing TP greedy site or a mandatory broadcast when that site is disabled. Each request’s eight exclusive virtual slots are permuted into accepted path order followed by the remaining slots in their original order. Target KV stays in its original physical slot. Original node-ordered target feature rows are handed to the ordinary DFlash projection and five-layer draft KV writer, which writes all eight private slots at their true depths. The committed prefix owns the selected path. The parent’s double-buffered bonus IDs, emitted IDs, lengths and next-step fields retain their original lifetime. The worker records a fresh scheduler event after the request-table update and the draft KV write before publishing its new lengths.

The startup guard excludes unsupported selector/target geometry, sliding ring addressing, sharded KV, DCP, prefill CP, attention DP, Mamba, correction models and simulated acceptance. Ordinary per-batch fallback handles sampling, grammar, log probabilities, logit modifications, idle batches and draft graph misses. A non-greedy batch on an eligible model still pays the captured 7×16×16 selector-score copy per request. [Dispatch guards and storage](dispatch_cpu.json)

## Verification and memory

Four held-out real Qwen prompts supplied 96 anchor requests. There were 67 branching proposals, 24 accepted paths with noncontiguous node indices and 417 checked serial continuation tokens. The Triton CPU interpreter matched 1,536 full/sliding argument rows against an independent attention oracle and 2,085 accepted five-layer KV pairs through the pinned worker method bodies. Reduced synthetic projection modules supplied the actual tensors for the physical-slot tests. Two real Gloo processes with different local proposals, target argmaxes and local physical sliding maps agreed on every emitted token and every retained/reserved request slot across eight requests. The compact metadata kernel compiled for SM86 and SM90 with int32 and int64 pool mappings. CUDA FA3, eight-process NCCL and the complete Muse worker remain unverified. [Oracle](../fixed_tree_adapter_cpu.json) · [Gloo](tp_gloo.json) · [Offline native code generation](compact_codegen.json)

The eager target uses one reusable metadata slab with capacity based on the largest admitted physical reservation bound. It creates no extra target CUDA graphs. At B32 and a 131,072-token bucket, the tensor allocations total 153,117,324 bytes per rank, including 128 MiB for full pages, 16 MiB for shared prefix and 2 MiB for sliding pages. A 32-request draft capture adds 229,376 bytes. A static identity vector with 1,893,609 entries adds 7,574,436 bytes. Unified mappings borrow storage from the allocator. Growth may transiently retain a former slab. The local B32 harness peaked at 238,789,120 allocated bytes, including its parent controls, virtual table and source maps. ## Local timing and the score gate

Both RTX 3050 SM86 trials use 12 reciprocal-order rounds with changing public selector inputs. The control repeats the scored parent’s page-metadata and greedy-acceptance routines. The tree arm copies the conditional scores, grows the proposal, gathers/stages real table shapes, runs the same parent metadata initialization, then walks and permutes owned slots. Native FA3, target model, TP communication, draft KV and scheduler work are outside these numbers. The tree arm uses ordinary eager GPU calls. GPU event time can include launch gaps on this device.

At equal serialized output, the six held-out surrogate prompts consumed 102 ordinary verification calls and 97 no-mass tree calls. The complete implementation would need its elapsed time per step within 5.15% of the parent at that central call ratio. As a scale comparison only, official B16 and B32 median decode rates and accepted lengths suggest about 81 ms and 103 ms per step. A 5.15% allowance corresponds to approximately 4.2 ms and 5.3 ms, respectively. This combines different models and devices and cannot establish an H200 gain. A second layout partitions eight nodes into disjoint ancestor chains. Each group needs one page table and a bottom-right causal FA3 query segment. It keeps each query exactly once and avoids the two-stage softmax. An independent CPU implementation checked 8,640 full/sliding outputs and their exact key sets. Capping proposals at four leaves retained the same 97 held-out calls with 2.41 active query groups per visited request. Three leaves gave 98 calls with 2.30 groups, and two leaves gave 100 calls with 1.80 groups. The segment variant has CPU evidence only.
