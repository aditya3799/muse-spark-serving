Experiment 1: one GEMM pair for all routes
bench_experts.py loads the scored Humming adapter and canonical packed weights. It replaces the four light/heavy launches with one W13 and one W2 tuned to expected rank-local work. Both paths include alignment, activation, scaling and final per-token reduction. Full H=I=4096, E=32, top-8 from 256 unique global experts. Five row counts, uniform and concentrated routing, 20 paired CUDA-graph measurements per case, three fresh correctness seeds and an activation change that must reject stale output.
Result: reject unconditional replacement. For 8-256 uniform rows the median baseline/candidate ratio was 1.002-1.006. For 128 and 256 clustered rows it fell to 0.750 and 0.738. Some clustered outputs also differed bitwise at 32 and 256 rows. The 753-row uniform gain of 1.051 is isolated and cannot justify the regressions. local_01/results.json has timings, conditional bootstrap intervals and reference repeat ratios.

Experiment 2: a single packed weight format for a fused expert port
qualify_packing.py checked the immutable v139 donor by SHA256. That original preparer retains specialized copies of the expert weights and uses rank-local start 0. The prototype writes one Hopper WGS representation directly, 256 output rows at a time, from rank-local weights. It matched every one of 56,623,104 bytes against the donor reference across W13 and W2 for two full-size experts. A one-bit code or scale mutation changed exactly one output byte. Peak temporary allocation above the final destination was 13,830,144 bytes per stage in this fixture, excluding existing input weights. Whole-model memory remains unmeasured.
A separate test emulated deferring the BF16 round until after activation. It differed on 118,729 of 262,144 elements against the scored scale and activation path; PyTorch and native activation implementations can also differ. Restoring the scored rounding order and using the same native activation matched all tested elements.

Experiment 3: compute directly from the one packed format
packed_gemm.py multiplies BF16 activations by NVFP4 weights directly from the packed buffer with FP32 accumulation. Both W13 and W2 consume the same format created above. The CUDA kernel dequantizes tiles in flight. An independent sampled FP64 oracle checked 17,100 outputs across 12 cases, including unaligned row counts, both halves of the gate/up projection and signed codes. All exact-input fixtures matched. Worst random relative L2 was 2.28e-6. Two corrupted-buffer controls triggered mismatches. This establishes arithmetic/addressing for a single expert. The prototype is a reference consumer. Its performance is unqualified.
The remaining high-value comparison is the optimized native Hopper fused expert through the normal SGLang target-verify path versus the scored Humming path. That needs the serving BF16 rounding sequence in the native epilogue, correct per-rank routing, shared workspace ownership under graph replay, and a performant prefill path using one resident weight layout. The tests above resolve packing and single-expert addressing only.

Experiment 4: time the single-format correctness reader
The register decoder implements the packed bit permutation with shifts and masks. It matched the lookup-table version on all output elements in the 12 tests, and retained the independent sampled FP64 results and corruption controls. packed_gemm_02 records the test. Across W13 and W2 at 8, 32 and 128 rows, 15 paired RTX 3050 timings measured 3.89-4.05x against the initial reader. Against an already-dequantized BF16 matrix and torch.mm with FP32 output, the register implementation still took 4.05-25.08x as long. The dense comparator uses more resident weight bytes and is a diagnostic here. Neither local reader qualifies as the serving performance path. Keep the register reader as an oracle for the native Hopper implementation; prioritize the native tile pipeline over additional scalar-decode tuning. reader_timing_01/results.json records raw samples and paired bootstrap intervals. Reproduce with launch_probe.py --script bench_reader.py --seconds 120 --out NEW_DIR.

Experiment 5. Native Hopper experts integrated into the scored Humming parent
Unscored serving job 0afdc0b191dd4b42 was accepted at 16 users with --moe-runner-backend humming on November 18. The exact patch is native_package_02/candidate.diff, SHA256 1ce48266f47574c5c0d4fd3c557b12f6d24811d03121f9bd9ea4e89965f6065c, 145127 bytes and 13 files. It passed git apply --cached --check --whitespace=error against 297e54fd. collect_hopper.py saves its latest judge status and result in native_package_02/h200_job.json. The job was queued when these findings were written.

The specialization covers BF16 top-8 experts with hidden and intermediate size 4096 and up to 32 local experts on Hopper. It keeps one packed weight layout for verification and prefill. Each CTA owns the full 4096-wide K reduction of each assigned output tile. The native path performs both expert projections and SwiGLU, writes raw BF16 results by route and uses the existing serving finalizer. Routing across ranks uses the scored layer's mapping. Large inputs use chunks of up to 384 rows. The adapter allocates 61874048 bytes of temporary workspace per invocation, and a 16384-row raw output occupies another 1 GiB. Total model peak memory and TTFT require judge measurement. Cooperative launch is checked before preparing the native weights. Look for the startup line containing 'Muse Hopper routed experts' and CUDA configuration status 0.

The packaged SM90a kernel compiled and linked both offline and through PyTorch's extension loader. The block needs 222592 bytes of dynamic shared memory. native_loader_03/results.json records the host ABI and scratch sizes. Native BF16 decode and activation code ran on RTX 3050 with 0 mismatches over 2097152 weight values and 262144 activation outputs. The direct packer processed both 32-expert banks and matched 84934656 bytes against an independent donor packer across three selected experts per stage. native_fragment_01 and native_pack_01 hold the receipts.
native_route_02 ran the final package's route builder, raw W2 scatter, Python serving forward and scored finalizer against an independently indexed CUDA reference. Eight shapes from 0 to 16384 rows covered invalid/remote IDs, a nonzero rank offset, concentrated routes, the 384-row chunk boundary and a 128-row CUDA graph replay with three changed inputs. The test supplied synthetic accumulators in place of matrix multiplication. Full Hopper TMA/WGMMA execution, generated tokens, per-load throughput, and model peak GPU memory are still unmeasured by these local tests.

Score interpretation. The measured four-load parent is 1.2363x. A 2x finish requires 1.6177x more throughput than the parent. At a hypothetical 2x expert acceleration, the experts must account for 76.37% of parent time to reach 2x overall under fixed-work Amdahl arithmetic. At 3x expert acceleration the required share is 57.28%. These are thresholds. The judge uses a four-load throughput frontier. No measured serving speedup is assigned to the candidate until judge data arrives.
