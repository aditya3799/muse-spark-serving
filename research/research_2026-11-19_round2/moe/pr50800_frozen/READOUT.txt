What is actually new compared with our existing WGS:
- Runtime token tiling: <=16local expert rows uses mma.sync; larger tiles use WGMMA
  widths24/32/40/48/56/64/72/80/88/96/104/112/120/128 to reduce padded compute.
- Persistent GEMM1/GEMM2 work queue, with GEMM2 waiting on the contributing intermediate
  row blocks, rather than a whole-grid barrier between the GEMMs.
- Optional two-CTA cluster tiles multicast token rows and share weight transfers.
  Auto pairing begins at16384total routes, subject to even row-block counts.
- PDL can overlap gather tails with grouped-kernel prologue. Dynamic route metadata
  remains on device and supports changed routing under graph replay in author's tests.

Precision and storage constraints:
NVFP4E2M1, positive finite E4M3 group16, BF16 activations and FP32 tensor-core accumulation
are real SM90 paths. No FP8 activation quantization is used. Upstream packs original
512code+64scale bytes per16x64 block, but rewrites scale bytes to normalized exponent
codes. This is a value-preserving representation only in its accepted scale domain.
Negative scales (including negative zero) and NaNs are explicitly rejected.
At zero scale it erases all FP4code bits, including negative-zero coefficient signs.

Its coefficient is W*2^-63, restored together with FP32global scale before BF16 output.
Our scored parent instead uses full-value coefficients, BF16 GEMM output, then a BF16
post-scale multiplication. Upstream also rounds SiLU before multiplication while the
parent silu_and_mul has kRoundActivation=false, and folds unequal up/gate into W2scale.
These change finite outputs. CPU receipt pr50800_coefficient_audit.json proves65664
packed words/2032positive-finite coefficient pairs, normal-range boundary differences,
and explicit exceptional-range shifted-product underflow/global overflow examples.
The changes alone do not decide challenge legality or model quality, but prevent a
claim of a drop-in exact scored-parent replacement. No arbitrary tolerance is proposed.

Muse adapter requirements before a runtime experiment:
1. Preserve our actual gate/up scale convention; disable the generic unequal-scale
   fold when following the scored parent. Preserve BF16 GEMM/post-scale and activation
   rounding boundaries, or explicitly gate a separately reviewed precision variant.
2. Request RAW route outputs (topk_weights=None); run existing per-expert Muse RMSNorm
   before routing-weight combination. Generic combined output skips that required op.
3. Add explicit custom Muse loader/dispatch hooks. Passing the new backend flag alone
   is rejected by the frozen Muse constructor; generic ModelOpt hooks do not own it.
4. Keep one persistent packed representation. Retaining the original plus donor-packed
   weights across60layers would exceed the2GB incremental budget by tens of GB. A
   transient repack is a compatibility strategy with measured cost, not a free fallback.
5. Bound shared route workspace/chunks and qualify actual multi-chunk capture. The raw
   op gathered+intermediate+output is196608*T bytes at Muse4096/top8; this is the SAME
   core size as parent cache13+cache2, not3.22GB of net new memory at16K. Peak must still
   include different lifetimes, metadata/order, postnorm, graph retention and repacking.
6. Preserve owner/weight-reload invalidation, serialization, PDL/capture lifetime and
   dynamic-routing liveness. No graph-safe wrapper is implemented in this research.
