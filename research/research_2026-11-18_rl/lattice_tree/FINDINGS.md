## Verifying fewer draft tokens

The online policy uses only a request's observed successes and reached draft positions. It estimates conditional acceptance with right-censored Beta counts and prices the graph bucket that would actually execute. On held-out GLM DFlash2 requests the simulation gave 1.058×, 1.053×, 1.117× and 1.172× as many tokens per unit of modeled time as verifying eight rows at each load. A constant-confidence control beat the adaptive policy at 32 users. This replay resamples individual rounds from real request-level observations and interpolates an isolated H200 layer cost, with an assumed common draft cost. [Replay and independent model control](width_search.json) · [Original public data](https://huggingface.co/datasets/UW-SyFI/servingstudio-workload)

The RTX 3050 pilot and an independent holdout then ran the actual frozen Humming rank-local expert pair, normalization and weighted output, including packing the chosen rows. The uniform pilot agreed bitwise in all twelve 16/32-user rounds. On the independent skewed input the compacted path changed 40,607 BF16 values across eight rounds at 16 users and 79,778 at 32 users. The uniform 32-user run changed 458. Its whole-candidate reward was −100 under the local correctness protocol. Even on the bit-exact 16-user uniform holdout, the observed timing combined with modeled acceptance gave 0.943× tokens/s. Preserving the dense kernel tile settings restored the 16-user skewed cases. An adversarial 32-user batch still changed 512 values. Giving the kernel the original dense expert counts restored the original output on the tested failures. Dropped target rows determine some of those counts. The diagnostic that reads the dense counts consequently has no measured production speed benefit. ## Spending a fixed verification budget on branches

The tree retains high-probability prefixes from the existing top-16 selector lattice, stores each node's parent and logical position, and only commits output along the verifier's greedy path. The independent causal-attention fixture checked 1,002 emitted tokens, and exhaustive enumeration validated 27 small trees. A plain causal mask allows attention into sibling branches and changes the result. These checks establish packing and commit semantics on the fixture. Actual Muse acceptance and Hopper tree-attention costs remain open. [Algorithm](selector_tree.py) · [Correctness controls](verification.json) · [DForkTree authors' paper](https://arxiv.org/abs/2611.12356)

The public 1.7B Qwen3 verifier and its matched DFlash2 checkpoint provide a way to check whether the proposal tree predicts real greedy continuations. Both use the seven-proposal, top-16 selector geometry. The experiment saves each actual target continuation and selector lattice independently, then compares the released greedy chain with learned width policies on request-disjoint prompts. Each policy must repay its changed target-step cost. [Experiment](public_pair/observe.py) · [Qwen3 DFlash2 model](https://huggingface.co/rasyosef/Qwen3-1.7B-DFlash2) · [ForeSpark budget scheduling](https://arxiv.org/abs/2611.13442)

The historical four-load frontier model gives a conditional design target for a fixed eight-row tree. If only acceptance changes, even committing all eight rows gives 1.704× stock in this model. If first- and later-turn prefill time both improve by 25% in throughput terms, it needs a mean 6.15 commits at every load for 1.8× stock, or 7.73 for 2×, with target-step time held fixed. The model uses reported latency percentiles and previously measured frontier slopes. Queueing, extra tree-attention work and hardware execution remain unmeasured. [Inputs, scenario grid and assumptions](frontier_requirements.json)

The fixed-width prototype builds branch prefixes, packs ancestor pages, translates the FA3 sliding window, and commits the selected path by permuting only a request's owned page-one slot IDs. On the CPU Triton interpreter the compact branch table equaled the original dense-mask ordering on 2,688 node rows. Across 213 live request cases, including 103 noncontiguous accepted paths, the commit preserved all 3,585 rejected reservation slots and the accepted writes in three disjoint KV fixtures. The suffix check compared over a million physical page entries. All four programs compiled for SM86 and SM90 at widths 8, 16 and 32. These fixtures exercise packing and ownership, and production integration still requires replay-safe publication to the scheduler and the actual target attention backend. ## Real local target and draft

The RTX 3050 generated 864 greedy tokens across 12 fixed prompts with the Qwen3-1.7B target and its matched DFlash2 checkpoint. We observed 780 eligible anchor lattices and split by request. At eight rows the selected tree used 95 verifier calls on the six held-out traces to the chain's 102, a 1.074× call ratio with a request-bootstrap interval of 0.979–1.152. At 12 and 16 rows it used 88 and 86 calls, respectively. Those arms must pay the additional cost of verifying more target rows. Learning depth/fork calibration on the discovery requests gave 1.063×, 1.146×, and 1.186× call ratios on the same held-out requests. A separately designed linear expected-commit policy preserved the original target shape but used exactly 102 calls on both arms. [Raw observations](public_pair/observed.json) · [Fixed-tree replay](public_pair/policy_replay.json) · [Fitted model](public_pair/calibrated_tree.json) · [Linear policy](public_pair/bellman.json)

Both live eight-row arms used real target forwards, exact causal or branch masks, a compiled planner, and actual KV/feature commits. Each matched all 240 checked serial target tokens. For 234 timed tokens per arm, the chain used 47 target steps and 37.81 s. The tree used 46 and 38.50 s. Its paired local throughput ratio was 0.982× with a 0.845–1.099 request-bootstrap interval. Four same-shape perturbations of all future target data left the anchor outputs bitwise unchanged. Comparing the public and pinned eager transition expressions found no changed row argmax in those four probes. These short reasoning-style Qwen outputs do not measure the private long-context Muse workload.
