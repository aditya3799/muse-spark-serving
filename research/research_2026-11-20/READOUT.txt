MoE: new GPU raw-scale converter
Implemented standalone CUDA conversion from the previously studied WGS packed layout to the raw-scale PR50800 layout.
Two implementations: generic dimensions and compile-time N=4096/8192 specialization. Three block sizes (128/256/512) tested.
Each implementation passed eight cases: two seeds, E=1/2, W2/W13 geometry. All 16 nibble values and all 256 scale byte values are included.
Compared GPU output against an independent NumPy forward packer, inverted it back to original codes/scales, checked unchanged source bytes and guard regions, and replayed CUDA graphs after changing source contents.
Peak PyTorch allocation was 150,996,992 bytes for each suite; this is the test allocation, not a production model residency measurement.
Paired confirmation: 18 alternating-order rounds, generic baseline and duplicate control, specialized candidate, exact equality each round.
E=1 N=4096: conversion-only 1.2434x; worst pair 1.2181x; control ratios 0.9848..1.0223
E=1 N=8192: conversion-only 1.3112x; worst pair 1.2955x; control ratios 0.9944..1.0059
E=2 N=4096: conversion-only 1.2521x; worst pair 1.2207x; control ratios 0.9975..1.0070
E=2 N=8192: conversion-only 1.3147x; worst pair 1.3078x; control ratios 0.9959..1.0019
This baseline is the new generic converter, NOT stock serving or scored Humming. No MoE GEMM, full FFN, model loader, H200 execution or serving throughput was measured.
One E32 layer of the two packed matrices totals 905,969,664 bytes (864 MiB). Retaining an additional converted copy across many layers would violate the memory budget. Production ownership/freeing and a viable exact fallback remain unsolved; do not integrate this as a serving speedup.
