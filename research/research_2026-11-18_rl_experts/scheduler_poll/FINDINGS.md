# Shared-memory notification for an empty scheduler poll

The frozen non-DP request receiver broadcasts an int64 size over its TP CPU group on every poll. When a request arrives it then broadcasts serialized bytes. The scored launch uses a single node with eight GPUs, TP8, EP8, normal overlap and scheduler_recv_interval=1. The pinned source creates a shared-memory MessageQueue on the same TP CPU group when SGLANG_USE_MESSAGE_QUEUE_BROADCASTER is true, its default. Its rank-zero writer matches the current global broadcast source. Runtime ring initialization is inferred from the pinned default and launch settings. The retained log does not print the resolved broadcaster or environment value. The candidate broadcasts a boolean through the existing ring only for a fully same-host, non-DP group. Empty polls return an empty list immediately. Every nonempty poll, including locally generated aborts on the leader, still takes the exact frozen Gloo payload path on every rank. Absent ring, multinode ring and other scheduling modes fall through. The eight-way HiCache Gloo MIN all-reduce still executes at the original site. Moving the cache counts before ingestion could miss same-tick changes caused by request processing, session reaping, chunk aborts, or queued backups. Local queue emptiness cannot prove other ranks have no completions or a matching reclaim digest. ## Timed CPU stage

The exact source methods for the receiver, raw Gloo payload broadcast, shared ring and on-node membership detection ran with eight separate CPU ranks on one WSL node. All ranks shared one copy-on-write PyTorch image. For each timed poll the ranks immediately performed the production-shaped four-int64 Gloo MIN, including a divergent local readiness counter and matching digest. The table reports median paired rank-max wall time saved per complete poll over 10 AB/BA rounds × 16 polls. The two independently seeded runs reversed their starting order. Controls repeated the original arm. [Trial](trial.py) [Pilot receipt](cpu_tp8_seed7951.json) [Holdout receipt](cpu_tp8_seed18272.json)

| Poll distribution | Pilot ratio and microseconds saved | Holdout ratio and microseconds saved | Holdout paired wins |
| --- | --- | --- | --- |
| Every poll empty | 1.392×, +1,019 µs | 1.240×, +708 µs | 9/10 |
| One arrival in eight | 1.286×, +792 µs | 1.320×, +903 µs | 10/10 |
| Every poll has a payload | 1.031×, +130 µs | 0.981×, −73 µs | 4/10 |

All eight ranks matched a changed 74,160-token payload, ordered messages and a local abort, both with the ring enabled and with the original fallback. The pilot/holdout baseline-versus-control median ratios across the three distributions span 0.963–1.042. These local stage times include Python, Gloo, device-availability checks with CUDA hidden, the framework-pinned ring, rank skew and OS scheduling. True H200 host hardware, arrival fraction, cache-ack distributions, GPU work and overlap were unmeasured. No defensible H200 score increment follows from the observed stage ratio.
