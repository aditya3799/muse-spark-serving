# Frozen Humming layout to a single grouped Hopper launch

The native adapter now consumes the Humming W13 and W2 weight banks and local route IDs used by the 1.2363× scored parent. The Linux SM90a library exports `okc_create`, `okc_run` and `okc_destroy`. Offline CUDA 13 compilation and a CPU-side dynamic loader test succeeded. The linked library is 215,256 bytes, SHA-256 `8890b2dfe748f86731cccf7a27b01038aef233116552bc3d1800d7289754f06b`. The available RTX 3050 cannot execute this kernel. **The whole FFN has an open H200 bit-parity and performance gate.** [Build receipt](host_build.json)

- `group_prep.convert` uses the frozen 64×16 Humming warp layout, with both HMMA and WGMMA mini-block orderings. One GPU kernel transposes the existing packed E2M1 nibbles to logical row-major weight bytes. A second reorders four E4M3 scale bytes per output feature into one uint32 per 64 K elements. Each operand retains its exact original bits. The per-lane inverse is derived from the companion expert-slab implementation. [Source](group_prep.py) [Independent forward packer](../../research_2026-11-18_rl/expert_slab/test_slab.py)
- `group_prep.route` locates valid top-eight routes in their original flattened order within each local expert. The device computes each expert's count, its exclusive row offset and its length rounded up to a multiple of 16. An empty expert gets 16 zero rows, avoiding zero-dimensional tensor maps. The 32 descriptors share constant weight/scale dimensions for each projection, while the activation/output row dimension changes per group. This retains one native grouped GEMM per projection and needs no device-to-host route-count read. The grouped CUTLASS path replaces each group's tensors and strides on device. The upstream example documents a uniform-shape limitation on group-wise scales. The scale-tensor dimensions in this adapter do satisfy uniformity, but an SM90a replay with variable routed row counts is still required. [Descriptor kernel and grouped launcher](group_host.cu) [Upstream grouped mixed mainloop](https://github.com/NVIDIA/cutlass/blob/cd9d8a7d612b6b9ad0f1b698925e31243e828629/include/cutlass/gemm/collective/sm90_mma_array_tma_gmma_rs_warpspecialized_mixed_input.hpp#L1215-L1268)
- W13 and W2 use one shared 576 MiB scratch allocation, overwritten between projections. A grouped row buffer replaces each of the two incumbent intermediate allocations. At H=I=4096, E=32, the extra 512 potential rows cost 12 MiB over the parent's two intermediates. At M=16,384, route ranks, two count matrices, group labels and other route arrays add about 1.13 MiB. This is roughly 589.1 MiB of additional tensor storage per execution stream, before CUTLASS workspaces, allocator rounding and temporary setup. One instance is designed to be reused across layers on its owning stream. Creating one per model layer would invalidate the bound. Repeated full-bank conversion reads and writes 1,728 MiB/layer before GEMM reads. The blank route groups can add as many as 512 computed rows on each projection. With little local work this is expensive.
- `group_runtime.GroupedFFN.forward` retains BF16 output restoration, the original per-expert global scaling and the parent's native SiLU kernel. It returns the same canonical output and local-ID shape. Invalid slots are initialized to zero. The output aliases scratch valid through the next call on the same stream, so its finalizer must consume it promptly. The hardware qualification fixture deliberately runs inside a nondefault current stream for CUDA graph capture. [Adapter](group_runtime.py) [Hopper qualify-and-reject script](qualify_hopper.py)

Two CPU Triton-interpreter seeds covered 417,792 packed coefficient/scale values in total against the frozen forward transform, including all 256 raw scale bytes and both mini-block transpositions. A further 430,080 BF16 values were checked through gather, padding and scatter. Cases changed routing within reused buffers, including all-remote and concentrated rows, invalid IDs on each side of the valid range, multiple scan blocks and empty experts. A byte-level check covers scale storage, including NaN encodings. The arithmetic proof for dequantized operands covers valid finite scales. [Preparation receipts](group_prep_checked.json) [Operand arithmetic](FP8_CONTROLS.md)

To qualify on a local Hopper with the pinned serving environment installed, build `build_host.py` against the pinned revision and run `python qualify_hopper.py --seed 77153`, followed by `--seed 91407`. Each seed changes packed coefficients, input values and routes, compares every live raw W2 and finalized output bit against the scored Humming path, and rejects on first divergence. Only passing cases produce event-timed parent/candidate/duplicate-parent observations. The default gate covers M=128,768,3072, uniform, concentrated and all-remote routing. `--rows` can extend it to 16,384 if single-GPU memory permits. None of these H200 comparisons has been performed.
