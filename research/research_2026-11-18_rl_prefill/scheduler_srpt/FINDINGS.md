# Shortest-remaining prefill on the scored Muse workload

The SSEngine 60-second aging preset produced a median 0.9889× FCFS wall-time speedup across the eight capacity-constrained C32 sensitivity scenarios (range 0.9829–0.9964). All policies processed exactly the same input tokens. Across concurrency 1, 4 and 16 the median wall-time ratio was 1.0000. These results do not support spending a scored run on the scheduling policy. [Raw CPU replay](replay.json) · [Replay program](replay.py)

The scored SGLang parent selects FCFS by default, budgets chunks of 16,384, and prioritizes an admissible prefill before decode when the prefill-decode interval is zero. Its existing shortest-prefill-first sorts waiting requests by uncovered work and can reserve part of an active chunk for shorter requests. Its existing HRRN ages waiting requests using the number of processed prompt tokens. SSEngine’s SRPT can place a waiting request before a started request at a chunk boundary. Its optional aging prioritizes overdue arrivals. The upstream “good” profile pairs a 60-second bound with a 32,768-token budget, even splitting and load budgeting. This comparison transfers the scheduling order and aging rule onto the scored 16,384-token budget. SSEngine itself generates one token per request. The CPU harness imports the pinned native sorting/active-chunk cap methods and SSEngine SRPT scheduling method via their ASTs. Admission, arrivals and execution are simulated. Each session makes 13 closed-loop turns with exactly 74,160 mean first-turn tokens, 753 mean new tokens per later turn and 220 mean output tokens. Four deterministic seeds vary request lengths. Cold requests either arrive together or over 1.2 seconds. Follow-ups start immediately or after up to 0.3 seconds. A shared GPU service gives admissible prefill priority. The prefill service time is affine and calibrated from the scored single-user first-turn p90. Decode uses four accepted tokens per step and interpolates the recorded per-user decode rates. The C32 primary scenarios reserve a request’s full context until its decode completes using the actual 1,893,608 full-cache capacity. A ten-million-slot control tests the assumption’s influence. The full output contains 40 scenarios × 7 policies. [Scored receipt](../../release_2026-11-18/scored_submission_status.json)

The judge published aggregate measurements. Its per-request arrivals and length samples, host-tier read latency, cache evictions, actual allocation headroom and per-size GPU service times are unavailable. The replay assumes full cold prefill and cached previous prefixes on later turns. Its absolute TTFTs and cache pressure are synthetic. It establishes that scheduling order can redistribute TTFT without reducing total work, and that the sign of any C32 gain depends on admission behavior. A real score estimate requires measured server behavior on the corresponding request stream.
