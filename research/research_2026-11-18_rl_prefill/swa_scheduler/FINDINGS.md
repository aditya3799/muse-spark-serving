# Sliding-window target-verification scheduler

The scored parent precomputes full-attention FA3 scheduler data. This patch prepares a separate plan for DFlash fixed-width causal sliding-window layers. In the scored geometry an ordinary windowed layer can use the same plan as the other 45 windowed layers on that rank. The plan contains three batch-aligned integer vectors and, on SM90, one mutable semaphore. At 32 requests this is 388 bytes per recording of the model graph. The scored full-attention plan remains independent.

Each eager verify prepares once after the page tables are final. During capture, SGLang already calls `init_forward_metadata_in_graph` before any model layer. The patch records the native planner here and the subsequent attention launches refer to its output. The CUDA graph owns the allocation and re-executes the preparation on every replay using current cache lengths and query offsets. Separate recordings can carry different addresses. The ordinary replay backend already refreshes its static page and length arrays before the model graph. There is no extra device-to-device copy or tensor persisted by a cross-forward lookup. The unchanged call that actually computes FA3 still receives its original query, both caches, page table, cumulative lengths, masks, window, output and split policy.

The standalone native planner uses the batch times the maximum query width as a fallback for `total_q`. Both preparation and consumption check the fixed-width geometry. Ragged layouts, compact-ragged graphs, custom masks, attention CP/DP, concurrent two-batch execution, prefill-aware SWA, mismatched windows, layer geometry, sequence objects, table objects, different softcap state and split counts retain the per-layer native calculation. A window spanning the entire table is skipped because the native fork canonicalizes it to full causal attention. With no K/V append, native forward disregards `cu_seqlens_k_new`. The standalone planner therefore receives None even though the original attention wrapper continues receiving its original argument.

The native scheduler increments its semaphore. With one split and an externally supplied plan, FA3 emits a separate semaphore zero after the forward. With multiple splits the native combine performs the reset, even if dynamic per-sequence splits are one. All layers use the same serving stream under the eligibility checks. Savings at one split therefore replace a preparation kernel with a reset kernel for each consumer. [Pinned FA3 forward and planner](https://github.com/sgl-project/sgl-attn/blob/f89bc2306632d1ec5f97b014dded4254f5b4a907/hopper/flash_api.cpp) and [combine reset](https://github.com/sgl-project/sgl-attn/blob/f89bc2306632d1ec5f97b014dded4254f5b4a907/hopper/flash_fwd_combine_kernel.h).

## Verification

The cumulative patch applies to the pinned upstream commit and its delta applies to the frozen 1.2363× package. Removing the three changes from the eager, in-graph, and attention methods recovers the original methods' ASTs. The verification executes the patched methods with real CPU tensors, a recorded native-planner mock and the real FA3 dispatch conditional. It ran 12 independent mock captures, 108 changed-input replays, 4,968 sequential attention consumer checks and 42 negative fixtures. The tests covered split requests 0, 1 and 4, 1–32 requests, 7–8 query rows and 8,192–131,072 cache slots. Tests check semaphore ownership and reset expectations, while the native reset itself is established by source and a previous native experiment. [Current patch verification](verification.json) and [cumulative patch](candidate.diff).

A previous experiment on the local RTX 3050 ran the installed native FA3 BF16 kernel with the same scheduler-sharing principle, through a different Python integration. It passed 768 checks across six changed-input settings. Native attention speedups ranged from 1.017× to 1.087×. The new metadata lifecycle has CPU integration coverage. Native E4M3 FA3 requires Hopper, so H200 full-layer or serving gains remain unmeasured. [Archived native results](../../swarm_2026-11-16/attention_speculation/phase2/swa_scheduler_reuse/native_run/results.json).

Run `python -X utf8 build.py` and `python -X utf8 verify.py` from this directory. The verification requires CPU PyTorch. The cumulative package SHA-256 is `86eb830667a9facde4a3dbb4e35aab962d66617634a1f2973fc77221d210af15`.
