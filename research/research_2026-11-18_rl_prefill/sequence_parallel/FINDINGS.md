# Sequence-parallel prefill for the scored Humming experts

The 1.2363× H200 parent reduces the full attention output, gathers the row-sharded pooler output, reduces every expert row, then gathers the unpooler output. Pinned SGLang already supports sequence-parallel attention and residuals on Muse, but its configuration requires FlashInfer TRT-LLM and the fused collective GEMMs require a Blackwell device. This experiment uses Humming's original rank-local expert weights and the ordinary linear methods surrounding existing TP collectives. [Scored receipt](../../release_2026-11-18/scored_submission_status.json) [Pinned SP implementation](https://github.com/sgl-project/sglang/blob/297e54fd105e974cdf401e5b4d20253a22c16f90/python/sglang/srt/layers/layernorm_sp.py) [Sequence-parallel decomposition](https://arxiv.org/abs/2205.05198)

The candidate reduces the attention BF16 projection to rank-owned sequence rows, leaves the FP32 residual stream on those rows and projects the selected rows with FP32 output before conversion to BF16. It gathers the normalized-input precursor for the unchanged Humming expert dispatch. Each rank reduces its rank-owned output rows, unpools them, then runs the existing FFN residual boundary. The next QKV projection gathers row shards and executes the original full-M matrix multiplication. Prefill requires 512 or more rows divisible by TP, the original Hopper BF16 model and widths, and ordinary TP/EP with attention CP/DP disabled. Decode, target verify and nondivisible eager tails run the parent. Full prefill graphs decide at their padded capture size. The eager tail checks the row count returned by the body before gathering, so a 753-token request captured at 768 rows gets its 753 real rows in order. ## Transport and capacity

At M=16,384 and TP8, all figures below are modeled MiB sent per rank for each routed layer. Timings for NCCL on H200 are unavailable.

| Parent | Sharded routing | Full-geometry gathered routing |
| ---: | ---: | ---: |
| 1,008.000 | 672.875 | 896.000 |

The parent figure includes the attention output, pooler, expert output and unpooler. The candidate includes each next-layer QKV gather. In addition, once per forward it communicates 1,120 MiB for all five DFlash taps and 224 MiB for the final BF16 hidden state. The target retains its FP32 residual locally, converts the tapped states to operator dtype at the same layer boundary as the parent, and gathers the concatenated BF16 taps before the logits processor selects rows. Per-rank memory for the complete packed BF16 tap output at 16K is 1.25 GiB, already needed by the parent. The actual allocator peak across graph buckets and H200 launch settings is unmeasured. By itself, the gathered-router path saves the same 112 MiB per layer as the previously tested isolated unpool reduce-scatter and adds these final gathers. The router-sharded path also removes seven eighths of the rank-local router computation. Dynamic plan selection and transport must be qualified before attributing timing gains. ## CPU distributed qualification

The SP tests perform actual BF16 Gloo all-gather, all-reduce and reduce-scatter with production SP entry, O projection, expert adapter, pool/unpool FP32 boundary and next QKV methods. A small deterministic routed expert supplies partials. Across four fixtures of 512, 520, 1,024 and 16,384 rows, TP2/4/8 returned bitwise-equal router IDs, expert output, residual stream, and next QKV input projection. The two TP8 variants also compared packed five-tap BF16 outputs with independently randomized rank-specific attention partials and perturbed positive/negative cancellation pairs. Full model widths, weights, kernels and CUDA graph replay on eight H200s remain untested. Windows TP8 encountered a worker access violation; the reported TP8 runs completed with Linux CPU Gloo using copy-on-write workers. NCCL may use a different reduction order, and GPU top-k sensitivity is measured separately below. ## GPU router

The initial native-row variant ran the scored 8192×512 packed high/low BF16 projection with separate FP32 accumulators and the pinned Triton sigmoid top-eight kernel. At 16,384 rows using eight 2,048-row shards, random inputs changed top-eight ordering on 8 of 16,384 rows at seed 723041 and 7 rows at seed 885127. Deliberately near-tied logits changed 4,563 and 4,784 rows. The signed-cancellation fixtures remained exact. Maximum random logit differences were about 0.000061. Each per-rank local router took about 1/5.19 of the full router time on the RTX 3050. These differences demonstrate a row-geometry effect in FP32 accumulation. Judge token agreements and end-to-end throughput remain unknown. The conservative implementation stores the gathered full-router geometry; the sharded native variant is retained for audit. ## Preserving full-M router geometry

Six new RTX fixtures compared every original rank offset at 16,384 rows and full router width. Reassembling the eight shards in original rank order reproduced every scored FP32 high/low component. Repeating a single rank's rows to 16,384 and selecting its original offsets also matched all 50,331,648 FP32 components, 786,432 top-eight IDs, routing weights and packed entries across the six fixtures. Fixtures included random weights, deliberately near-tied experts and signed cancellation. Repeating per layer cost 167.64 and 168.25 ms median against 89.32 and 89.17 ms for the original router on the two random seeds. The duplicate native controls took 89.01 and 89.16 ms. Retain the gathered router as the conservative fallback. [All 48 original-rank comparisons](repeat_gpu.json) [Standalone replayer](repeat_gpu.py)

The isolated private-scratch variant allocates one initialized full-shape buffer per forward and copies only the current rank's hidden rows at each layer. It carries that buffer explicitly from the model into each sparse layer, so the layer side streams are ordered by the ordinary join and wait. At 16,384 rows the live temporary is 256 MiB per rank. The original global M, high/low packed weight and FP32 output remain unchanged. Unknown shapes follow the existing dispatcher. The layerwise `repeat` timing above measures a different implementation.
