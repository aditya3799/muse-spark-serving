# Bounded Hopper BF16 grouped expert consumer

The prototype calls the native SGL DeepGEMM grouped BF16 operation. Each cohort/row chunk launches one grouped GEMM for W13 and one for W2, across all active experts in that cohort. The FP32-accumulating native BF16 kernel compiled offline to both model-width SM90a cubins. Both contain `wgmma.mma_async.sync.aligned.m64n128k16.f32.bf16.bf16` and BF16 rounding. The exact public wheel SHA-256 is d1e3e1421d6624a16f32f2dee35c026d64d2f77799e5c0c5eaba68c27023630c. The compile probe fixes a supported tile config, while the runtime chooses its config through the device heuristic. The parent Humming adapter owns packed NVFP4 weights, FP8 block scales and BF16 W13/W2 global scales. The prototype materializes eight experts from the existing packed weights, once per cohort. W13 takes 512 MiB and W2 takes 256 MiB for the 4,096-wide rank-local expert. Three reusable token buffers add 160 MiB at 512 input tokens, top-8 and 128-row alignment. The runner supplies one reusable workspace and serializes use on its model stream. Its 928 MiB of BF16 storage excludes the caller's original output, small routing vectors, CUDA allocator and vendor runtime overhead. Alignments 64 and 256 use 912 and 960 MiB. The function checks geometry with an extra 16 MiB routing allowance. A serving integration must reserve that memory before sizing the KV pool, and qualify serialization before sharing it across CUDA graphs. [Scratch arithmetic](cpu.json)

The native `use_psum_layout=True` mode encodes actual ends after alignment-padded group starts. The sorter uses the flattened route slot as stable identity. The gather derives its token by integer division by top-k, and the scatter writes back to the original top-k slot. A missing expert emits no native tiles. Remote and invalid slots remain untouched in the caller-provided output. The consumer leaves the original W2 global scale for caller finalization when deferred, otherwise applies it after the BF16 down output. The W13 global scale is applied after the W13 output and before SiLU. The CPU Triton interpreter compared 10 routing fixtures at two seeds and both global-scale modes. Inputs included duplicate slots, uneven assignment, no local experts and one token. The complete runner also passed four comparisons against ungrouped references over the actual packed inverse mapping, both Humming mini layouts, per-expert global scales, fixed workspace addresses and untouched remote outputs. CPU substitutes for grouped CUDA math, post-scaling and SiLU are listed explicitly in the receipt. [Routing differential](cpu.json) · [Complete runner differential](runner_cpu.json)

A different SM86 dense-GEMM experiment using the same conversion mismatched 12,289 of 524,288 final BF16 elements at 128 rows. The maximum absolute difference was 8.0, despite matching all 32,000 sampled packed coefficients. In the grouped prototype, materialized weights carry the original candidate’s quarter-scale convention and a factor of four is restored after its BF16 output. For tiny finite outputs the position of that BF16 rounding is consequential. A CPU sweep found 128 counterexamples. Tensor-core reduction order can also differ. Numerical acceptance on Hopper remains open. The bounded triangle of conversions, packing and execution also means 256 native GEMM launches in the 16,384-token, 32-expert worst-sized forward with this configuration, in addition to routing and activation.
