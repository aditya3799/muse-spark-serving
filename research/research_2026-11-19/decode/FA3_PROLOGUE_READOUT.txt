Mechanism and scope

boundaries, with each K task also storing its raw V head. FP8 output bytes use
a software implementation matching this installed Torch CUDA cast. Native
FA3 attention, softmax, output norm, target blocks and communication are not
executed by this fixture. There is no integrated serving patch.

Correctness
All65,536 BF16 input bit patterns match actual Torch CUDA BF16-to-FP8 bytes,
including every NaN encoding, infinity and signed zero. Two independent
controlled seeds pass all12 cases: M8/32/56/57/128/256, full and rotary/SWA
locations,8 changed-input graph iterations each. Q bytes and complete K/V
backing pools agree exactly; reserved slot0 stays untouched. Positions and
sparse physical destinations change in-place between graph replays, and
random, integer and signed scaled inputs are exercised. The56/57 threshold
keeps the native18-head _triton_config behavior. No software output tolerance.

Limits and historical context
Single SM86 GPU, synthetic QKV values and pool mappings, software conversion,
warm graph repetition, exclusive GPU slot. No clock/power telemetry series was
collected for this bounded screen; duplicate controls are present. H200 native
conversion, model activations, full attention and full serving remain untested.
The older decode_qkv fusion used20-head rows and a BF16-to-FP8 lookup table;
its later wider decoder-chain result was neutral. This is an18-head reduction
layout and packing refinement, not a new fusion boundary or a2x serving result.
Production scale/pool/ownership guards remain design requirements in
NATIVE_FA3_PROLOGUE_FUSION_PLAN.txt, not an implemented serving adapter.
No remote job, quota request, scored submission, or release change from this
lane. Frozen output-N package and queued candidate remain unchanged.
